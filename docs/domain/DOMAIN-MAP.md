# DevHarness CLI 领域图（草案）

范围来自 [产品草案](../product/PROJECT.md)。以下是同一工具包内的职责边界，部署单元仍为现有 CLI 工具包。
- **安装｜AC-01**　安装器先核对清单，逐一列出未解决的冲突并在复制前停止。维护者确认手工合并后，重跑须保留合并内容、补齐缺件，再次运行无新增改动。
- **运行标识｜AC-05**　主控通过 `start` 关联原始请求、`feature_id` 和 `change_id`。原请求重试复用原 run；同一对标识换请求时报告冲突，保留原请求和进度。
- **验收｜AC-02**　`bugfix` 离开 `reproduce` 前，验收清单须非空并覆盖任务引用的 AC。此时冻结验收定义，后续可补状态和证据；删项或修改预期须回到复现阶段。
- **任务｜AC-03、AC-04**　规范与复现记录按内容冻结，变更使最早受影响阶段回退、下游证据失效。授权源码即使列入输入也可编辑，须按新版本测试。`implementation` 须指出未完成任务，所有任务均为 `done` 且其余门禁满足才可推进。
- **证据与恢复｜AC-06**　隔离样例先留存通过记录，再提交引入回归的源码。`resume` 应回退到最早受影响阶段，使下游证据及批准失效。重跑原命令记录失败，修正后重新取证并由用户重新确认人工门禁，用提交差异、阶段记录和前后日志串起全过程。

交 M0 规划确认：维护者如何标明已合并的文件，以及任务包如何区分冻结依据与授权修改的源码。
